# Runtime Pipeline Provisioning

Runtime startup provisions the execution pipeline only after identity and continuity context are available.

The provisioning layer assembles:

- Court policy path
- local Court signing key
- persistent replay ledger
- execution receipt sink
- empty approved-executor registry
- default-deny safety check

Default local paths:

```text
/opt/velvet/state/policy/court_policy.json
/opt/velvet/state/court/signing_key.bin
/opt/velvet/state/execution/consumed_tokens.jsonl
/opt/velvet/state/receipts/execution.log
```

The Court signing key must already exist locally and contain at least 32 bytes. It is never generated by Runtime startup and must not be printed or committed.

Provisioning fails closed when the Court policy, signing key, replay ledger, or receipt infrastructure cannot be loaded safely.

The executor registry starts empty. No hardware executor becomes available merely because Runtime booted. Executors must be registered explicitly by trusted local integration code.

The safety check also starts in deny mode. Until a real role-specific safety gate is provisioned, all executor requests are refused.
